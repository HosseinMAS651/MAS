# MAS — مدیریت اتاق سخنرانی

نسخهٔ بازنویسی‌شدهٔ MAS بر پایهٔ ساختار فعلی مخزن، با تمرکز روی پایداری تایمر، ضبط خودکار، نمایش عمومی زنده و امنیت مسیرهای مدیریت.

## قابلیت‌های کلیدی

- ضبط صدا بدون دکمهٔ جداگانه؛ شروع/توقف/ادامهٔ ضبط با تایمر هماهنگ است.
- پایان زمان اصلی، تایمر را متوقف و تصمیم «ادامه سخنرانی / اتمام سخنرانی» را نمایش می‌دهد.
- پایان سخنرانی فایل ضبط را نهایی می‌کند و به سخنران بعدی می‌رود.
- حذف سخنران با سه انتخاب «ذخیره ضبط / حذف ضبط / انصراف» انجام می‌شود.
- هر اتاق یک لینک عمومی و QR اختصاصی دارد.
- صفحهٔ عمومی بدون ورود فقط برای تماشا است و فایل‌های مجاز اتاق را به‌صورت زنده به‌روزرسانی می‌کند.
- لینک‌های عمومی هرگز فایل‌های ضبط‌شده را در اختیار تماشاگر قرار نمی‌دهند.
- CSRF، مدیریت نشست، محدودسازی تلاش‌های ورود، محافظت مسیر فایل و کنترل مالکیت در مسیرهای مدیریتی اعمال شده‌اند.

## اجرای محلی

```bash
python -m venv .venv
.venv\\Scripts\\activate
pip install -r requirements.txt
uvicorn main:app --reload
```

روی Linux/macOS:

```bash
source .venv/bin/activate
```

در حالت توسعه، در صورت نبود `DATABASE_URL` از SQLite محلی استفاده می‌شود.

## استقرار روی Render

`render.yaml` برای یک Web Service تنظیم شده است. مقدارهای `MAS_SECRET_KEY` و `DATABASE_URL` باید در محیط Render تنظیم شوند.

**نکتهٔ مهم دربارهٔ فایل‌ها:** ذخیرهٔ محلی `./uploads` روی سرویس Free Render برای نگهداری دائمی فایل قابل اتکا نیست. برای پایداری واقعی ضبط‌ها و فایل‌های آپلودی باید Storage دائمی/ابری یا دیسک پایدار متناسب با پلن سرویس تنظیم شود. کد فعلی این مسیر را پشت `MAS_STORAGE_DIR` متمرکز کرده تا مهاجرت Storage جداگانه بعداً ساده باشد.

## مهاجرت دادهٔ موجود

راه‌اندازی برنامه قبل از استفادهٔ عادی، جداول موجود را بررسی می‌کند و ستون‌های جدید موردنیاز نسخهٔ جدید را به‌شکل additive اضافه می‌کند. رکوردهای موجود اتاق‌ها و فایل‌ها حذف نمی‌شوند.

پوشهٔ `uploads` و فایل دیتابیس محلی عمداً در Git نادیده گرفته می‌شوند و نباید داخل مخزن commit شوند.
