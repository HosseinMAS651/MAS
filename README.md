# مــاس — MAS

سامانهٔ مدیریت اتاق‌ها و زمان‌بندی سخنرانی‌ها؛ شامل صفحهٔ عمومی تماشاگران، ضبط صوتی از مرورگر، آرشیو قابل پخش، فایل‌های ارائه و حالت سخنران با کد ورود.

## راهنمای استفاده

### مالک اتاق

1. وارد حساب شوید و اتاق را بسازید یا از صفحهٔ ویرایش اتاق، گزینهٔ **حالت سخنران** را روشن کنید.
2. از صفحهٔ جزئیات اتاق، پیوند عمومی یا QR را برای تماشاگران بفرستید. همان صفحه کد چهارکاراکتری هر جایگاه سخنران را نشان می‌دهد؛ در صورت نیاز کد همان سخنران را بچرخانید. روشن/خاموش‌کردن حالت سخنران کد را عوض نمی‌کند.
3. تایمر همچنان فقط در اختیار مالک اتاق است. وقتی مالک تایمر را برای سخنران فعال کند، اگر سخنران از صفحهٔ عمومی وارد شده و میکروفون را در همان دستگاه آماده کرده باشد، ضبط از همان دستگاه آغاز می‌شود. روشن‌کردن حالت سخنران برای فعال‌شدن این ضبط کافی است؛ گزینهٔ ضبط معمولی اتاق مانع آن نیست.
4. برای پذیرفتن فایل از سخنران، گزینهٔ **اجازهٔ ارسال فایل سخنران** را روشن کنید. فایل‌های ارسالی ابتدا در صف خصوصی می‌مانند و فقط پس از تأیید مالک برای نمایش عمومی در دسترس قرار می‌گیرند.
5. از بخش آرشیو می‌توانید فایل صوتی را مستقیماً در مرورگر پخش کنید یا جداگانه دانلود کنید. دسترسی و نمایش عمومی فایل‌ها همچنان تابع تنظیمات اتاق و وضعیت تأیید آن‌هاست.

### تماشاگر و سخنران

- پیوند عمومی را بدون ساخت حساب باز کنید. اگر حالت سخنران خاموش باشد، صفحه فقط برای تماشاست. اگر روشن باشد، نقش **تماشاگر** یا **سخنران** را انتخاب کنید.
- سخنران کد چهارکاراکتری مالک را وارد می‌کند. در هر لحظه فقط یک دستگاه با آن کد معتبر می‌ماند؛ ورود دستگاه تازه نشست دستگاه قبلی را جایگزین می‌کند.
- پس از ورود، برای وضعیت «آماده» دکمهٔ فعال‌سازی میکروفون را بزنید و اجازهٔ مرورگر را بدهید. تا وقتی مالک نوبت را با تایمر فعال نکرده، ضبطی انجام نمی‌شود. صفحه را هنگام نوبت باز نگه دارید و از اتصال HTTPS و مرورگر به‌روز استفاده کنید.
- هشدار نوبت با صدا/لرزش و اعلان مرورگر به پشتیبانی و مجوزهای سیستم‌عامل وابسته است. اعلان پس‌زمینه را می‌توان از صفحه درخواست کرد؛ با بسته‌شدن صفحه یا قفل‌شدن گوشی، تحویل اعلان یا ضبط تضمین نمی‌شود.

### بازیابی رمز عبور

- هنگام ثبت‌نام یک **کد بازیابی یک‌بارمصرف** نمایش داده می‌شود. آن را همان لحظه در جای امن نگه دارید؛ سامانه فقط هش کد را ذخیره می‌کند و متن کد بعداً قابل نمایش نیست.
- کاربر واردشده می‌تواند از صفحهٔ پروفایل با رمز فعلی، کد تازه بسازد. کد تازه، کد قبلی را باطل می‌کند.
- اگر رمز و کد بازیابی را هر دو از دست داده‌اید، بازیابی عمومی ممکن نیست؛ مدیر سرور باید از ابزار `scripts/reset_password.py` استفاده کند. این کار نشست‌های فعال را باطل می‌کند و کد بازیابی قبلی را پاک می‌سازد.

## اجرا در محیط توسعه

پیش‌نیاز: Python 3.11 یا بالاتر، Node.js 20 یا بالاتر و npm.

```bash
python -m venv .venv
source .venv/bin/activate                 # ویندوز: .venv\Scripts\activate
pip install -r requirements.txt -r requirements-dev.txt
cp .env.example .env                     # در ویندوز: copy .env.example .env
```

برای محیط توسعه مقدار `MAS_SECRET_KEY` در `.env` را با یک مقدار تصادفی جایگزین کنید. برای نمونه:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

سپس در دو ترمینال اجرا کنید:

```bash
# ترمینال اول، از ریشهٔ مخزن
uvicorn main:app --reload --host 0.0.0.0 --port 8000

# ترمینال دوم
cd frontend
npm ci
npm run dev -- --host 0.0.0.0
```

برنامهٔ توسعهٔ فرانت‌اند روی `http://localhost:3000` در دسترس است و درخواست‌های `/api` را به API محلی می‌فرستد. برای اجرای یکپارچهٔ تولید، Docker فرانت‌اند را build می‌کند و API روی پورت `8000` هر دو را ارائه می‌دهد.

## استقرار و حفظ داده‌های موجود

- پیش از deploy از PostgreSQL و فایل‌های storage نسخهٔ پشتیبان بگیرید. migrationها برای افزودن ستون‌ها و indexهای جدید طراحی شده‌اند و ردیف‌های کاربران، اتاق‌ها، سخنرانان، ضبط‌ها، chunkها و فایل‌ها را بازنویسی یا حذف نمی‌کنند؛ بااین‌حال پشتیبان مستقل پیش از هر ارتقا ضروری است.
- هنگام جایگزینی کد، `DATABASE_URL`، `MAS_SECRET_KEY` و مسیر/باکت storage فعلی را عوض نکنید. تغییر URL پایگاه داده یا storage می‌تواند برنامه را به داده‌های خالی دیگری وصل کند، حتی اگر migration ایمن باشد.
- در محیط production از PostgreSQL استفاده کنید و `MAS_SECRET_KEY` را در بخش secrets سرویس میزبانی نگه دارید؛ `.env` واقعی را در ZIP یا Git قرار ندهید. برای storage محلی در Render، دیسک پایدار لازم است؛ در صورت استفاده از S3/R2/MinIO، متغیرهای `MAS_S3_*` را فقط در secret manager تنظیم کنید. Dockerfile پشتیبانی boto3 را هم نصب می‌کند؛ برای نصب غیرداکری، `pip install -r requirements-s3.txt` را اجرا کنید.
- Blueprint رندر از `DATABASE_URL` موجود استفاده می‌کند و آن را خودکار جایگزین نمی‌کند. health check آماده‌بودن سرویس در `/ready`، سلامت وابستگی پایگاه داده و storage را هم می‌سنجد؛ `/health` فقط زنده‌بودن فرایند را بررسی می‌کند.
- تنظیمات در زمان startup اعتبارسنجی می‌شوند. برای ساخت مدیر، ابتدا حساب را عادی ثبت‌نام کنید و سپس روی سرور اجرا کنید:

```bash
python scripts/create_admin.py
```

برای بازنشانی دستی رمز یک کاربر روی سرور، پس از تنظیم همان `.env`/`DATABASE_URL` تولید:

```bash
python scripts/reset_password.py
```

## آزمون و build

```bash
pytest -q
ruff check mas_app tests scripts
cd frontend
npm run typecheck
npm run build              # build also runs the typecheck
```

برای دیدن صفحه‌های راهنمای API در محیط توسعه از `/docs` استفاده کنید. اطلاعات schema/API نباید جای کنترل دسترسی endpointها را بگیرد.

## ساخت بستهٔ ZIP برای جایگزینی فایل‌های پروژه در GitHub

اسکریپت بستهٔ نهایی را از ریشهٔ مخزن می‌سازد:

```bash
python scripts/package_zip.py
```

خروجی `mas_v2_release.zip` شامل source، migration، تست‌ها و bundle لازم فرانت‌اند است و `.git`، محیط مجازی، `node_modules`، cache، `.env` واقعی، پایگاه داده و پوشه‌های فایل/آپلود محلی را کنار می‌گذارد. بسته، نسخهٔ پشتیبان از داده‌های production نیست.

برای جایگزینی کد در GitHub، ZIP را در یک پوشهٔ موقت باز کنید و فایل‌های پروژه را روی checkout مخزن/شاخهٔ موردنظر اعمال کنید؛ سپس `git status` را بازبینی کنید، به‌خصوص حذف فایل‌های build قدیمی. `.git`، `.env`، پایگاه داده و storage محلی را حذف نکنید. پس از بازبینی تغییرات، فایل‌های منبع را commit و شاخهٔ خود را push کنید؛ `DATABASE_URL` موجود را حفظ کنید تا startup migration روی همان داده‌ها اجرا شود.
